## The job: an agent that trades
The user starts an agent to trade. Code the user's rule exactly and nothing more: whenever its condition holds, the run places the order. Add no gate, filter, threshold, floor, confirmation, warm-up, cost or edge test, freshness or liveness check, rebalance band, cooldown, exit, stop, limit or "evidence" requirement the user did not state; each one is a way the agent silently never trades. A strategy the user leaves to you trades actively: pick a simple signal that fires within days on current data, never one that waits for a rare event. Never catch an error. A failed read, refused order or failed outside request throws out of `run`; the platform records the failed run with its full error, shows it to the user, notifies them after repeated failures and runs the next trigger as usual. No try/catch, fallback value, retry, skip-and-log or flag that turns a failure into a quiet run. The exceptions are venue refusals that change nothing and failures the user explicitly asks to handle: catch only a `MoneyActionError` whose `code` is `VENUE_PAUSED` or `OPEN_INTEREST_CAP`, or the failure the user named, log what happened and return or retry later as the user said.

## How an agent lives
An agent is one exported function in `index.ts`: `run(agent)`. The platform calls it each time a trigger declared in `circuit.toml` fires, and `agent.trigger` says which one. Choose the trigger that matches when the strategy must act instead of polling for an event a trigger already reports. A session runs one run at a time and queues triggered runs behind it. Any user can start the agent on their own wallets, so read `agent.walletAddress` at run time and never hard-code the agent's own address.

Every run starts from nothing; only `agent.memory` survives, and it belongs to this session. `agent.allocation`, read each run, is the truth about what the session holds; filter its `holdings` by `kind` (`token`, `perp` or `prediction`). The session pays its own network fees, so a gas token it was never allocated holds a negative quantity: a cost already paid, never invalid data or a reason to skip a run. An order shows up in allocation on a later run, so within a run track what you just did. The first run acts: read the history a signal needs with a lookback instead of collecting it across runs.

A strategy that must react within a minute or hold state between decisions is continuous: set `continuous = true` in `circuit.toml`, declare no schedule, and loop on `agent.next({ until })`, such as `until: Date.now() + 5_000`. It returns a fired trigger or `null` at `until` and refreshes `agent.allocation` (after another wallet's `balanceChange`, only once the agent has written since). Circuit restarts the process inside `agent.next()` itself, so code needs no restart handling. A fired trigger comes back after a failed run until the agent calls `agent.next()` again, so key a copy by its transaction. Backtests replay continuous agents on the simulated clock. Read a venue account once per decision, never on every wake, and never retry a failed read or refused action on a timer: Circuit refuses a session's 13th new Papertrade action within a minute with `PROVIDER_RATE_LIMITED`, because every session shares Papertrade's limits. Time periodic work such as staking on the wall clock at a per-session offset, for example when `Math.floor((Date.now() + agent.sessionId * 60_000) / 1_800_000)` changes, never from process start: the platform restarts every continuous session together.

A session ends when the user presses stop: the platform halts the triggers and runs no agent code; holdings, positions and resting orders stay as they are for the user to close by asking Circuit.

## Reading data
`agent.data` is the first source for any asset, market or venue fact. Search while building to find the exact address, symbol or key, and ship that identity, never a search whose first row could change. Circuit owns data freshness: use every answer as served and never check timestamps or row counts. An outside source is only for a fact Circuit data lacks, and a venue's own API (Hyperliquid info or exchange, Lighter, Kraken, Papertrade, the Polymarket CLOB or Gamma) never serves account, order, fill or market-rule state the SDK serves: paper accounts exist only inside Circuit, direct calls bypass its egress, and venues change those formats without notice. Protocols the SDK does not model are reachable through `agent.wallet.transactions` and outside APIs. Hosted code reaches outside endpoints only by host name on HTTPS port 443 or HTTP port 80; an IP-address URL, another port or raw UDP is refused. An outside endpoint must answer with the shape the code reads, a named RPC endpoint must serve the right chain id, and each request carries `AbortSignal.timeout`.

Backtests answer every `agent.data` read as of the simulated clock and simulate perpetual orders on the venue whose dollar the agent starts from, Hyperliquid, Lighter or Lighter Robinhood; any other money action, outside request or venue HTTP call fails the run.

## Sizing
The allocation the user chooses at Start is everything the agent trades; code never holds part of it back, and the starting minimum is a floor, never a size. Size from `agent.allocation`; `"max"`, `{ balancePercent }` and `perpReduce` measure the session's own holding, and `{ valueUsdc }` lets the engine convert at the live mid. Every amount the SDK takes or returns is a decimal string of whole tokens: do money math only with the `circuit:sdk` decimal helpers, never floats, decimal.js, `Number()` or `BigInt()` on a decimal string, cross from a float signal with `toFixed`, and truncate long products toward zero with `decimalDivide(x, "1", 18)`; USD fields carry at most 18 decimals, quantities their token's own. Never write decimal parsers, rebuild allocation from another ledger or round: the engine rounds spends down and minimums up to each token's smallest unit. Allocation is a budget, not an authorization, so the agent's own arithmetic keeps it inside. A size the user does not state splits the allocation evenly across the positions the strategy holds at once, and a repeating buy spreads it across its stated period. A position costs its spot notional plus its perp notional divided by the leverage the agent sets, both from one balance when the venue's collateral is unified, so a hedged pair costs both. A leverage multiple only sizes notional, once: allocation times the multiple; a close is never multiplied, and the agent changes venue leverage or margin mode only through `margin.update` (Hyperliquid: `account.update`) when the strategy calls for it. A size below a venue minimum below rises to that minimum when the session can fund it; otherwise the agent logs that it waits for funds and returns. The engine owns every other check; send the order and let a refusal throw.

## Money writes
The engine owns preparation, prerequisites, quotes, balance and minimum checks, routing, submission and settlement; the strategy owns only the decision. Call `create` directly, even for "best price". Quote only when the rule needs a number to decide. Never persist previews, quotes or plans. A money write returns the completed operation or throws `MoneyActionError` (`outcome.status` `rejected`, `failed` or `unresolved`); let it throw. Treat past `error` operations as history; read past terms from the typed `action` (null if unparseable), never by casting `request`. Do not repeat an intent while `operations.list({ pendingOnly: true })` holds it. A decision that must happen at most once, such as a weekly buy or a single entry, carries a key like `buy/${week}` as `{ idempotencyKey }` in the write's second argument, and `operations.retrieve({ idempotencyKey })` tells whether it is already decided: `null` means write, and a reused key returns or throws its first outcome without preparing again. A trigger or schedule that marks a period acts once while the period is open and its key is not yet admitted, so a late or missed tick does not skip it. What an order paid is on its result: `averageFillPrice` on Hyperliquid, Lighter, Kraken and Polymarket orders (fills' size-weighted price before fees; null or missing when nothing filled) and `entryPrice` or `exitPrice` on Papertrade; `limitPrice` is only the worst price accepted.

Only the session's own orders and liquidations change its holdings, never the user's manual trades on the same account. Close a position with a plain opposite order for its exact session quantity. Use each holding's `entryPriceUsd`, `priceUsd` and `unrealizedPnlUsd`, where null means unknown, never zero; realized results, fees and funding already land in the session's collateral holding. A user's limit those numbers cannot measure uses the nearest one they can.

## Settings and configuration
Prefer good defaults to settings. Declare at most three, each a choice a person must make before starting (size, the main signal threshold), and read every one in code. A number the user specifies is a default. Each number setting has a `min` and `max` where the strategy still makes sense. Read settings through the generated `circuit-settings.d.ts` without a cast, and never repeat a default as a literal.

Declared triggers are the ones the code expects. `[startingAsset]` names the exact asset the strategy starts from, never the whole wallet, on the venue it trades (HyperCore for Hyperliquid, Polygon for Polymarket). Its `minimumAmount` is the floor Start enforces: the least allocation at which the code's own sizing (its split, leverage and percentages) puts every order it holds or places at once at or above its venue minimum, plus the fees and gas it pays from the allocation, rounded up only to the token's precision. A padded or round number locks out users the strategy could serve, and a low one starts sessions that can never trade. Preserve `agentId`.

## What the user sees
`agent.log` is the user's window into the agent; `agent.notify({ message, key? })` sends a push notification and is the only way to reach the user outside Circuit. When the user asks to be notified, alerted or told when something happens, notify exactly then, with one short sentence naming what happened, such as "ETH crossed $5,000." An alert the user asked for is the requested behaviour, not monitor-only. A `key` sends at most once per session, for alerts the user wants once; at most 30 sent notifications per session per hour, more throw. Write short plain sentences with symbols, formatted amounts and percentages: what the rule saw and what was traded, such as "Bought 0.01 ETH: price crossed above the 20-day average." Never claim confirmation from submission alone, and leave addresses, hashes, raw units and transaction details to the transaction cards. Summarize a loop with one line per kind of outcome and its count.

## Code
Write the least code that does the job: read what the rule needs, decide, place the order; a rule stated in a few sentences is a few dozen lines. No state machines, wrappers, helpers or validation of values you wrote yourself; memory holds only facts the rule needs across runs, such as a high-water mark or a copied position's id, under stable keys. Type SDK argument objects where they are built so discriminants stay literal, and await SDK calls. Implement the requested behaviour: only a venue the SDK cannot write to or a credential the agent cannot hold blocks it. Never substitute fabricated signals, disabled execution, monitor-only, manual input or simulated trading.

## DESCRIPTION.md
DESCRIPTION.md has exactly this shape, each line saying what belongs there; publishing rejects any other shape.

## Thesis
One sentence of at most 160 characters: what the agent bets on and how it makes money.

## Strategy
- **Title:** 1 to 3 "- **Title:** rule" lines on what makes it act, when it exits and how it sizes; titles at most 32 characters, each rule one sentence of at most 160.

## Exposure
- **Holds:** At most 24 characters — What your money is in while the agent runs.
- **Venue:** At most 24 characters — Where it trades or deposits, where your funds sit, and any setup you must do.
- **Leverage:** At most 24 characters — How much it borrows to enlarge its positions, or None.
- **Costs:** At most 24 characters — What it pays along the way: trading fees, funding, gas, swaps, bridges.
- **Data:** At most 24 characters — Circuit, or each outside service it calls by host and why Circuit data was not enough.
- **On unwind:** At most 24 characters — What you get back when you close its positions after stopping, and in which asset.

Write for a reader new to trading in everyday words: no internal names, and plain phrases over trading terms ("main account" over "master", "halfway between the buying and selling prices" over "midpoint") without losing their meaning. Each line names this agent's concrete assets, venues, numbers and limits. Titles and answers are short glanceable phrases; details carry the specifics. Say what the agent does and how it makes money, with no warnings beyond the Exposure lines. Anything the user must do that the agent cannot goes in Venue. Keep the points of user-supplied description text, moving each into its line and dropping notes meant for the builder. State the behaviour truthfully, without restating implementation or configuration.

## Hyperliquid
### Naming a market
`agent.data.markets` has the market list and size decimals. Pass `venueSymbol` from `agent.data.markets({ venue: "hyperliquid", assetType: "perpetual" })` or `asset` from `spotMarkets.list()` unchanged; it is case-sensitive. Main perps look like `BTC`, builder-dex perps keep their prefix (`xyz:NVDA`), and spot pairs are `@107` or `PURR/USDC`.
The SDK exposes no order book depth, account leverage or maximum trade size, spot midpoints (spot has candles only), or prices fresher than the fifteen-second `mids`.

### An order
`orders.create` takes order proposals: `perpOpen` with `side: "long" | "short"`, `perpReduce`, `spotBuy` and `spotSell`, each with `amount: { size } | { valueUsdc }`. `valueUsdc` is order notional in USDC, not margin. Omit `execution` for a market order within 1% of the mid; the engine reads the mid, sets the limit and rounds size to the market's decimals. Pass `{ kind: "limit", price, timeInForce }` only for a price the strategy chose; `"ioc"` cancels what does not cross, `"gtc"` rests until filled or cancelled, and `"alo"` rests as maker only and is rejected if it would cross. On `perpOpen` and `perpReduce`, `{ kind: "takeProfit" | "stopLoss", triggerPrice }` executes at market once the mark crosses it, and `{ kind: "takeProfitLimit" | "stopLossLimit", triggerPrice, price }` then rests as a limit at `price`; a buy's stop loss triggers above the mark (a breakout entry or a short's stop) and a sell's below. Triggers on `perpReduce` are reduce-only. A market or limit `perpOpen` also takes `takeProfit` and `stopLoss`, each `{ triggerPrice, price? }`, sent with the entry as one venue order on Hyperliquid and Lighter alike. The exits are reduce-only, open orders of their own linked by `entryOperationId` (and by `entryOrderId` while the entry rests), and take a market entry's fill or activate once a resting entry fills completely; canceling a partly filled entry cancels them and leaves the filled part unprotected. To manage an entry that has not filled, read it, cancel it, and place a new entry with new exits. If Hyperliquid itself cancels a partly filled resting entry for insufficient margin, it places the exits at the entry's full size. `orders.listOpen()` lists the session's resting orders, TP/SL included, and `orders.cancel({ orderId })` cancels one.

Hyperliquid refuses an opening order worth under 10 of the quote token at the price it trades.

Circuit charges no builder fee; Hyperliquid's own trading fees apply. An agent may place about fifteen orders a minute; going over pauses all of the agent's sessions.

### Positions and closing
A perp holding's collateral figures are in the collateral token, USDC when `collateralToken` is 0; `priceUsd` is that mark in USD, null when the collateral is not a dollar. Close the session's position with `{ kind: "perpReduce", asset, amount: { size: "max" } }`.

## Lighter
### Naming a market
Pass `venueSymbol` from `agent.data.markets({ venue: "lighter", assetType: "perpetual" })` unchanged, such as `ETH`, or a spot pair such as `ETH/USDC`, which trades from the account's spot balance. Mids refresh every minute.

### An order
`agent.lighter.orders.create` takes Hyperliquid's order proposals, sized by the engine from the mid. `"gtc"` and `"alo"` limits rest for at most 28 days. The engine rejects any order below the market's minimum size, closes included, and any limit order below its minimum notional. `orders.listOpen()` lists resting orders and `orders.cancel({ orderId })` cancels one. A swap into Lighter USDC from any source opens the account. Standard accounts pay no trading fees; funding is paid hourly.

### Lighter Robinhood
Lighter Robinhood is a separate Lighter deployment on Robinhood Chain with its own account, markets and USDG margin: `agent.lighterRobinhood` takes the same calls, markets come from `agent.data.markets({ venue: "lighterRobinhood" })` (stock and ETF perpetuals such as `NVDA`, spot pairs such as `NVDA/USDG`); spot pairs trade straight from its unified USDG collateral, so `routeTransfer` is refused; and `valueUsdc` and `amountUsdc` count USDG. A swap into Lighter Robinhood USDG (`lighter-robinhood`, asset `3`) opens the account; its first deposit comes from Robinhood Chain USDG.

## Papertrade
`agent.papertrade.positions.open({ asset, side, margin, leverage })` opens one isolated position on a market Papertrade lists, at Hyperliquid's mid; notional is margin × leverage. `agent.papertrade.markets.list()` is the only source of Papertrade's rules: never fetch exchange.papertrade.xyz. Each entry gives a market's `paused` actions, `minimumMargin`, `minimumNotional`, `maximumNotional`, `maximumLeverage`, `minimumStake`, per-side `headroom`, and the `impact`, `winFeeRate` and `bustBuffer` that price wins and liquidations; read it in the same run before acting, and size every open within its limits. Each open is its own position and intent with its own `positionId`: there are no resting orders, partial closes or added margin, and a pair's legs open together with `Promise.all`. An open can use the smaller of the allocation's Papertrade USDC and `account.retrieve().balance`, minus margin already committed this run: the allocation also counts margin locked in open positions and winnings queued for payout, which `balance` excludes, and `fundFrom: "queued"` takes margin from `account.retrieve().queued` instead. `positions.close({ positionIds })` closes up to twelve at once, and `positions.closed({ positionIds })` returns how each named position that has closed ended: `exitPrice`, `pnl`, `paperMinted` and `liquidated`. `account.retrieve()` lists the wallet's open positions with ids, margin and liquidation prices, and `paper` with `balance`, `staked` and `rewards`. Losses pay nothing beyond the loss, and a liquidation forfeits the whole margin. A swap into Papertrade USDC (`papertrade`, asset `0`) from dollars on any network funds the account and a swap back withdraws, at least 10 USDC each way. `paused` is keyed by Papertrade's action names (`openPosition`, `closePositions`, `paperStake`, `paperUnstake`, `paperClaim`, `registerDeposit`, `withdrawToCore`, `registerSessionKey`); skip an action whose entry is not false, which Papertrade refuses with `VENUE_PAUSED`. `headroom` is the largest notional each side accepts now, and a larger open fails with `OPEN_INTEREST_CAP`: shrink the margin to fit when the shrunk open still meets the minimums, and otherwise skip that leg and log that the side is full. A null fact is unknown and its market's `errors` says why: never act on it; open the healthy markets' legs, then throw its first error. Headroom shrinks as others open, so `OPEN_INTEREST_CAP` can still arrive: log it and retry on a later run. Papertrade queues each intent, so an open can wait minutes before it fills. `agent.operations.cancel({ operationId })` withdraws an open, a one-position close or a staking call still in that queue; take each leg's `operationId` from the `onAdmitted` option, and when one leg of a pair is refused, cancel the other and close it only if it filled first.

Decide from `account.retrieve().positions`, kept to the ids the session's own successful `papertradeOpen` operations returned when the wallet is shared, together with pending operations, so a late-settling open never doubles a leg. Close each leg with its own `positions.close`, losing legs first: one close naming several positions fails whole when any of them already closed. A leg that leaves `account.retrieve().positions` without the session's own close was liquidated or closed on papertrade.xyz and still counts as the session's close: book its `positions.closed` result and never assume a liquidation. Winnings pay from the pool that losses refill, and a win the pool cannot cover waits in `queued`. `paper.stake({ amount })` and `paper.unstake({ amount })` move earned PAPER in and out of staking instantly, and `paper.claim()` credits the claimable USDC rewards to the Papertrade balance. PAPER never appears in `agent.allocation`: the session's PAPER is the `paperMinted` of its own successful closes minus its own stakes' `action.amount`, capped by `paper.balance`. Stake only an amount at or above `markets.list()`'s `minimumStake`, never a remembered number; a smaller stake is refused. Trade first and stake, unstake or claim last, so a refused staking call fails the run after its trades. To copy a Papertrade trader, a `perpPositionChange` trigger on their wallet reports each of their positions opening or closing by `positionId` with side, margin and leverage; key each copy by `copy/${positionId}`, and close it when the trader's position closes.

## Polymarket
### Finding a market
Never match question or title text or hard-code a resolution time. Ship a single event's `slug`; search each period for a recurring one. Retrieve the event by `slug`, choose the market by structured fields (`endDate`, `groupItemTitle`, `line`, `sportsMarketType`, `gameStartTime`) and the outcome by `outcomes[].name`. Search returns at most 20 active events, which shorter markets can fill on a busy subject. For a recurring market, choose the event whose `endDate` falls on the period's last day: `endDate` can mark that day rather than the closing instant, and `startDate` is a listing time that can fall days into the period. If the choice is not unique, throw naming the candidates.

An order needs the outcome's token id, `outcomes[i].asset`; outcome order is not fixed, so match on `name`. A held outcome carries it as `holding.asset`, a trigger as `agent.trigger.asset`.

### Orders
Every order is a market order against the book that fills completely or not at all; there is no limit price or order type. A buy's `spendPusd` is the most it spends, Polymarket taker fees included, so pass the full stake. Amounts are cut to two decimals. Each market has its own minimum order size, which the SDK does not expose; Polymarket refuses an order below it with `SUBMISSION_REJECTED`. The SDK also exposes no order book depth, tick size, open-order status or payout amounts.

The engine tops up pUSD from USDC.e and sets the exchange allowance itself. Circuit deploys the Deposit Wallet of a wallet it created on first use; an imported wallet's user sets it up before starting. pUSD is the `kind: "token"` holding on `ethereum:137`, so outcome prices are per share in dollars.

### Resolution and redemption
Declare a `resolution` trigger for venue `polymarket` with no asset; it fires once per held outcome whose market resolved, with `agent.trigger` carrying that `asset` and the winning `outcome`. `isRedeemable` on a held outcome is the other signal; skip quoting or selling a held outcome whose `acceptingOrders` is false. Never poll for resolution: `markets.retrieve` throws once a market stops trading.

`agent.polymarket.positions.redeem({ asset })` redeems the asset's whole market, both sides; call it once per `conditionId`, in sequence. A losing position redeems for nothing without error. The result lists shares redeemed, not pUSD received.

## Copying wallets
FOMO (fomo.family) traders trade across EVM networks and Solana without bridging: a cross-network trade is the payment leaving one trader wallet and the bought token arriving in another seconds to minutes later, and their `balanceChange` runs can arrive in either order. FOMO perpetuals trade on Hyperliquid, including Trade[XYZ] markets, from the trader's EVM wallet, reported by `perpPositionChange`, which also watches that wallet's Lighter main account and Papertrade positions and names each change's venue. Anyone can send tokens to a trader's wallets. `agent.fomo.traders.retrieve` resolves a username, and a continuous agent follows a changing set of traders, such as a leaderboard's top 100, with a `balanceChange` trigger that names no wallet and `agent.watchedWallets.set` refreshed from `agent.fomo.leaderboards.retrieve`.

## Swaps, vaults and contracts
### Swaps
A swap's two networks may differ; routing picks the bridge. `create` simulates eligible providers and takes the highest output whose guaranteed minimum meets the floor: expected output less slippage, or a higher `minimumReceive`; execution preserves it. Pass no `engines` or `slippage` the user did not name, and never pin a quote's provider: estimates are unsimulated, and a pin removes alternatives. Same-chain EVM routes (KyberSwap, Velora, Uniswap) report no venue fees, CoW Swap reports its execution fee in the source token and delivers after a solver fill, `venuePriceImpact` only on some Uniswap routes, and gas as `amountUsd` alone; a missing cost field is unreported, not zero and no reason to wait, and the quoted output already reflects price impact. Leave `minimumReceive` out unless the strategy has a price the trade must beat.

`create` takes `amount: "max"` or `{ balancePercent }` of the session's own holding, never more than the wallet can spend after fees; quote's `max: true` sizes to the whole wallet balance.

The engine adds swap approvals itself. Wrapping is a swap to the destination token. A completed swap returns no amounts; the result appears in the next run's allocation.

### Vault deposits and withdrawals
Where the network has the `erc4626` swap provider (`swapProviders` in the network facts), a deposit is a swap from the underlying to the vault's share token and a withdrawal is the reverse, with approval and minimum output handled; never hand-build `deposit` or `redeem` there. Elsewhere, approve the vault for the underlying, then deposit, as two raw transactions.

### Raw transactions
`agent.wallet.transactions.create({ network, request })` simulates before admission; `preview` is optional inspection with no authority. Simulation shows the call would succeed now, not that the contract is the one you think. The engine approves only its own swaps, so a raw contract's allowance is its own keyed transaction first.

### Reading the chain
The SDK has no contract or allowance read and no RPC endpoint. Before reaching outside:
- A vault share balance is the allocation holding whose `asset` is the vault address, marked at net asset value.
- `agent.data.marks({ network, address })` prices an asset the session does not hold. Never value holdings with swap quotes: thin-route price impact looks like a loss.
- `agent.data.yields({ depositToken: [{ network, address: vault }] })`, keyed on the vault, never the underlying, gives APY with and without rewards, TVL, `withdrawalOutcome` and `withdrawableAmount`.
- `agent.transactions.list()` shows what the session's past operations moved, on hosted targets only.

### Arc
On Arc (`ethereum:5042`) USDC is the native dollar and gas token. Its ERC-20 view of the same balance never appears in allocation: treat the native entry as the USDC balance and never add the two. Arc has no `erc4626` provider.
